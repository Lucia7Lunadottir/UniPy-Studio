# Архитектура UniPy Studio

Этот файл объясняет, **из чего состоит программа и как части общаются друг с другом**.
Если в будущем нужно что-то поправить или добавить — начинайте отсюда: здесь написано, в какой файл идти.

> Коротко: UniPy Studio — редактор кода на PyQt6 для Linux. Умеет C# (Unity), Python/PyQt и ещё много языков.
> Это «Visual Studio-подобная» среда: вкладки, обозреватель решения, подсказки, ошибки, терминал, запуск.
> Всего ~9300 строк Python в пакете `studio/`, интерфейс переведён на 12 языков.

---

## 1. Главная идея в одной картинке

```
              ┌──────────────────────────────────────────────┐
              │                  app.py                      │
              │  запускает программу, следит за «одним окном │
              │  на проект», аккуратно всё выключает         │
              └───────────────┬──────────────────────────────┘
                              │ создаёт
                              ▼
              ┌──────────────────────────────────────────────┐
              │              mainwindow.py                   │
              │   ГЛАВНОЕ ОКНО — «дирижёр». Держит всё:      │
              │   вкладки, панели, меню, настройки           │
              └───┬───────────┬───────────┬──────────────┬───┘
                  │           │           │              │
         вкладки  │   панели  │  анализаторы кода        │ вспомогательное
                  ▼           ▼           ▼              ▼
             editor.py    panels.py     lsp.py       theme.py, i18n.py,
          (один файл =  (обозреватель, intellisense.py  templates.py,
           один редактор) вывод, ошибки,  (подсказки)    search.py, updates.py
                          терминал…)
```

**Главный принцип:** окно (`MainWindow`) — единственный, кто знает про всех.
Редактор, панели и анализаторы **не знают друг о друге** — они общаются через сигналы Qt
(«что-то случилось → окно передаёт дальше»).

## 3. Как программа запускается

Всё происходит в `app.py → run(args)`:

1. Создаётся `QApplication`, ставится перевод Qt.
2. `launch.resolve_request(args)` решает, **что открывать**.
   Если дан файл внутри Unity-проекта — корнем считается папка, где есть `Assets/` и `ProjectSettings/`
   (даже если `.sln` ещё нет). Иначе ищется ближайшая папка с `.sln`/`.slnx`.
3. **Один процесс на проект.** `ProjectInstance` берёт «замок» (`QLockFile`) и открывает локальный сокет.
   Если такой проект уже открыт — новая команда уходит в старое окно, а новый процесс сразу завершается.
   Именно поэтому двойной клик по скрипту в Unity не плодит окон и не теряет несохранённые вкладки.
4. Применяется тема (`theme.apply`), создаётся `MainWindow`, восстанавливается раскладка панелей.
5. `launch.apply_request` открывает проект и файл, поднимает окно наверх.
6. Запускается цикл событий Qt (`app.exec()`).
7. **Аккуратное выключение:** останавливаются фоновые потоки и серверы, окно удаляется,
   Qt дорабатывает отложенные события. Порядок важен — иначе Qt может вызвать обработчик уже удалённого объекта.

В `app.py` также есть `ScreenshotRunner` — режим для автоматических скриншотов (для документации/тестов).
А `sys.excepthook` перехватывает исключения, чтобы PyQt6 не закрывал программу целиком из-за ошибки в обработчике сигнала.

## 4. Главное окно (`mainwindow.py`)

`MainWindow.__init__` собирает всё в таком порядке:

1. Настройки: `QSettings("UniPyStudio", "UniPyStudio")` и поверх него `Options` (`options.py`) — шрифт,
   перенос строк, подсказки, документы, автовосстановление, порог перезапуска анализаторов.
2. `JediWorker` — фоновый поток подсказок Python.
3. **Службы анализаторов** по реестру `languages.SERVICE_FACTORIES` (`csharp`, `python`).
   К каждой подключаются одни и те же сигналы: `finished`, `diagnostics`, `status`, `restarted`, `log`.
4. `CSharpIndexWorker` — фоновый поток, который сканирует проект и пакеты для C#-подсказок.
5. Интерфейс: `_build_central` (вкладки) → `_build_docks` (панели) → `_build_actions` → `_build_menus` → `_build_toolbar` → `_build_status`.

Окно само почти ничего не делает — оно **связывает** части. Действия живут в своих классах,
каждый получает ссылку на окно (`self.win`) и берёт у него только нужное:

| Атрибут окна | Класс | Что делает |
|---|---|---|
| `commands` | `commands.CommandRegistry` | Все команды и их клавиши; `_build_actions` только регистрирует |
| `nav` | `navigation.NavigationHistory` | «Назад / Вперёд» |
| `runner` | `run_control.RunController` | F5 / Shift+F5 (что именно — решает набор из `toolchains/`) |
| `builder` | `build.BuildController` | Ctrl+Shift+B, Ctrl+Alt+F7, Shift+F6, Ctrl+Break |
| `checker` | `build_check.FileCheck` | Ctrl+F7 |
| `refactoring` | `refactor_actions.RefactorActions` | Shift+F12, F2, Ctrl+R Ctrl+F, лампочка |
| `project` | `project_actions.ProjectActions` | Новый файл, скрипт Unity, PyQt-дизайнер, requirements.txt |
| `analyzers` | `analyzer_control.AnalyzerControl` | Надпись состояния, перезапуск, обновления |
| `safety` | `document_safety.DocumentSafety` | Изменения файлов на диске, автовосстановление |
| `debugger` | `debug.controller.DebugController` | F5 (отладка), F9, F10, F11, Shift+F11, Ctrl+Shift+F5 |
| `vcs` | `vcs.controller.VcsController` | Git: статус, полоски, коммит, ветки, Ctrl+0 Ctrl+G |
| `tests` | `testing.controller.TestController` | Ctrl+E,T; Ctrl+R,A / F / T; Ctrl+R,Ctrl+T |

Редактор и панели по-прежнему зовут окно (`jump_to`, `navigate`, `move_type_to_file`, `apply_code_action`,
`run_file`) — это тонкие передачи в нужный класс, чтобы им не знать, кто внутри отвечает.

Что остаётся в самом окне:

- **Вкладки:** `open_path`, `close_tab`, `save_current`, `save_all`. Сюда же — запоминание открытых файлов.
- **Параметры:** `_option_changed` применяет смену любого параметра (окно, меню и клавиши идут через `options.set`).
- **Панель поиска `FindBar`** (Ctrl+F) — поиск и замена внутри открытого файла.
- **Смена языка интерфейса** без перезапуска (`_change_language`).
- **Перезапуск анализаторов** по порогу памяти (см. раздел 7).

## 5. Редактор (`editor/`)

`CodeEditor` — наследник `QPlainTextEdit`. **Один открытый файл = один `CodeEditor`.**

Что внутри:

- `LineNumberArea` — номера строк слева.
- Умный ввод: автоотступы (`_newline`, `_indent`, `_dedent_brace`), парные скобки (`_auto_pair`, `_skip_closing`),
  умный Backspace, комментирование (`toggle_comment`), дублирование строки.
- Подсветка парных скобок и одинаковых слов (`update_selections`).
- Подсказки: окно автодополнения (`QCompleter` + `CompletionDelegate`), всплывающая подсказка параметров (`CallTip`),
  всплывающая справка при наведении (hover).
- Чтение/запись файла с определением кодировки (`decode_source`).
- Правила языка берутся из `languages.Language` (знак комментария, блоки `{}` или `:`).

**Важное правило:** редактор никогда **не ждёт** ответа анализатора. Он отправляет запрос и идёт дальше.
Когда ответ приходит, он сверяется с номером запроса (`req`) — устаревшие ответы выбрасываются.
Поэтому набор текста не «тормозит», даже если сервер думает.

## 6. Как работают подсказки (самая сложная часть)

Подсказки приходят **из трёх источников**, редактор не различает, откуда именно:

```
        Редактор спрашивает: «что подставить здесь?»
                          │
        ┌─────────────────┼─────────────────────┐
        ▼                 ▼                     ▼
   Python/PyQt       C# (быстрый путь)      C# (точный путь)
   JediWorker        CSharpProvider         Roslyn через LSP
   (поток)           + unity_api            (отдельный процесс)
                     (справочник Unity)
```

### 6.1. Python — `JediWorker` (`intellisense.py`)
Фоновый поток с очередью запросов. Умеет: дополнение, сигнатуры, hover, ссылки, переименование, переход к определению.
Если `jedi` не установлен — остаются подсказки «по словам» (`word_items`).

### 6.2. C# «пока сервер грузится» — `CSharpProvider` + `unity_api.py`
Roslyn загружает решение долго. Чтобы подсказки были сразу, есть свой лёгкий разбор:
- `unity_api.py` — встроенный справочник классов Unity (`MonoBehaviour`, `Transform`, `Vector3`…).
  Данные записаны текстом в `_SPEC` и разбираются один раз при импорте в объекты `Member`.
- `CSharpProvider` разбирает цепочки вроде `transform.position.` и ищет типы в пакетах проекта.
- `CSharpIndexWorker` делает тяжёлое сканирование диска в отдельном потоке и **склеивает** запросы
  (если вы быстро печатаете, обрабатывается только последний).

### 6.3. C# и Python «по-взрослому» — языковые серверы (`lsp.py`)
**LSP** — стандартный протокол «редактор ↔ сервер языка». Сервер работает в **отдельном процессе**.

Слои в `lsp.py` (снизу вверх):

| Класс | Роль |
|---|---|
| `JsonRpcConnection` | Обмен сообщениями с процессом по stdin/stdout. Читает по сигналу Qt — без потоков и ожиданий |
| `LanguageServer` | Один сеанс сервера для одной папки: запуск, `initialize`, синхронизация текста, диагностика, запросы |
| `CSharpServer` → `RoslynServer`, `CsharpLsServer` | C#. Основной — Roslyn от Microsoft, запасной — csharp-ls. Читают `.sln`/`.csproj`, которые создаёт Unity |
| `PyrightServer` | Python: pyright (проверки как в Pylance). Есть `ProjectAttributeIndex` — чтобы не ругаться на атрибуты, которым значения присваивают динамически |
| `LanguageService` | **Набор серверов одного языка** по корням проектов. Именно его видит окно. Следит за памятью |
| `CSharpService`, `PythonService` | Конкретные службы: «сервер на каждое решение» и «сервер на каждый Python-проект» |

Все источники отдают результат в **одном формате**: `{"kind", "req", "editor", "data"}`.
Окно получает его в `_worker_result` и находит нужный редактор по `id(editor)`.

### 6.4. Свежесть данных (важно для Unity)
- `intellisense.package_documents` хранит текст каждого `.cs` в `_FILE_CACHE` и перечитывает только изменившиеся файлы (по времени и размеру). Раньше каждые 5 секунд читались все файлы проекта.
- `CSharpService._watch_projects` каждые 2 секунды смотрит `.sln`/`.csproj`; если Unity их пересоздал, Roslyn получает `workspace/didChangeWatchedFiles`.
- Удаление и переименование файлов из обозревателя тоже сообщаются серверу (`MainWindow._tell_analyzers`).

### 6.5. Список подсказок: кнопки, сортировка, одинаковые имена
- Внизу списка полоса кнопок (`CompletionPopup` + `CompletionFooter` в `editor.py`): фильтр по видам (классы, методы, свойства…) и кнопка «A→Z» (по алфавиту / по релевантности). Виды описаны в `intellisense.KIND_GROUPS`, отбор и сортировка — `intellisense.arrange`.
- Если анализатор отдал весь список (`CompletionList.incomplete == False`), при наборе слова он фильтруется на месте — без нового запроса на каждую букву (`CodeEditor._refine_completion`). После Backspace делается новый запрос.
- Одинаковые имена из разных библиотек: вставляется именно выбранная строка (`_activated`). Порядок — `intellisense.completion_tier`: сначала выбранное раньше, потом UnityEngine, потом остальное. Выбор запоминается (`MainWindow.remember_completion`, ключ `intellisense/choices`).
- Меню «Вид → Подсказки из неподключённых пространств имён» (`lsp.OPTIONS["unimported"]`): выключить — Roslyn отвечает быстрее, но `using` сам не добавляется.

### 6.6. Лампочка быстрых действий (`Ctrl+.`)
- В левом поле редактора у текущей строки появляется лампочка, если есть что предложить; клик или `Ctrl+.` открывает список.
- Действия берутся у сервера (`LanguageServer.code_actions`: быстрые исправления и рефакторинги Roslyn/pyright) и из самой программы (`CodeEditor._own_actions` в `editor/quick_actions.py`, пока одно — «Перенести тип в отдельный файл»).
- Выбранное действие сервера уточняется (`resolve_code_action`) и применяется (`RefactorActions.apply_code_action`, окно только передаёт вызов): открытые файлы правятся в редакторе (одно Ctrl+Z), закрытые — на диске, новые файлы создаются.

### 6.7. Перенос типа и лишние using/import
`RefactorActions.move_type_to_file` выбирает исполнителя по языку (`MOVERS`: C# — `_move_csharp`, Python — `_move_python` через `refactor_python.py`).
Для C# анализатор по очереди оценивает два варианта файла: «только переносимый тип» и «всё остальное» (`LanguageServer.usings_report`). Из нового файла убираются using, не нужные типу; из старого — те, что были нужны только ему. Если после переноса появляются новые ошибки или анализатор не ответил, using остаются как есть (безопаснее лишний using, чем ошибка сборки).

## 7. Контроль памяти анализаторов

Roslyn и pyright могут разрастаться до гигабайт — а ваша цель: лёгкие программы.
Поэтому `LanguageService`:

- каждые 30 секунд (`CHECK_EVERY_MS`) смотрит память процесса **и всех его потомков** (читает Linux `/proc`);
- если превышен порог (по умолчанию 1 ГБ, настраивается в меню) **и** вы не печатали 2 минуты
  (`IDLE_BEFORE_RESTART = 120`) — тихо перезапускает сервер;
- после перезапуска окно заново отдаёт серверу текст открытых файлов (`_lsp_restarted`).

## 8. Расширяемость: реестр языков (`languages.py`)

Чтобы добавить язык, достаточно **одной записи** `Language(...)` в списке `LANGUAGES`:

```python
Language("rust", "Rust", (".rs",), "//", braces=True)
```

Поля: расширения файлов, знак комментария, `braces` (блоки в `{}`) или `colon_blocks` (блоки после `:`),
свой подсвечиватель или имя лексера Pygments, и `service` — ключ анализатора.

Файлы, которых нет в реестре, всё равно подсвечиваются, если Pygments знает язык (`for_path`).
Без Pygments они показываются простым текстом (`PLAIN`).

Чтобы подключить **новый анализатор**: написать класс службы в `lsp.py`, добавить фабрику в
`SERVICE_FACTORIES` — окно подключит все сигналы само, цикл по `services_by_key`.

### 8.1. Наборы инструментов (`toolchains/`) — запуск, сборка, новые проекты

Язык в `languages.py` — это то, как файл **редактируется** (подсветка, отступы, анализатор).
Набор инструментов — то, что с проектом **делают**: запускают, собирают, создают. Окно не знает,
что такое Python, .NET или Unity: оно спрашивает каждый зарегистрированный набор.

| Набор | Узнаёт решение | Запуск (F5) | Сборка | Новые проекты |
|---|---|---|---|---|
| `toolchains/unity.py` | есть `Assets/` + `ProjectSettings/` | открыть проект в Unity | `dotnet build` в кэш UniPy | — (Unity Hub) |
| `toolchains/python.py` | есть `.py` | файл выбранным интерпретатором | проверка синтаксиса в потоке | консольное, PyQt6 |
| `toolchains/dotnet.py` | `.sln`/`.csproj` (не Unity) | `dotnet run --project` (Exe/WinExe/веб) | `dotnet build` | всё из `dotnet new list` (Avalonia и др.) |

Интерфейс — `toolchains/base.py` (`Toolchain`): `applies`, `run_targets`, `target_for_file`, `run_command`/`launch`,
`build_jobs`, `build_jobs_for_file`, `clean`, `load_templates`, `create_project`, плюс `file_extensions`/`file_names`
(какие файлы показывать в обозревателе). Всё, что набор знает о решении, приходит в `ProjectContext` —
набор не трогает окно, поэтому его можно проверить тестом без интерфейса.

**Как добавить язык или платформу (например, Rust):**
1. `languages.py` — `Language("rust", "Rust", (".rs",), "//", braces=True, service="rust")` (редактор, подсветка).
2. По желанию — анализатор: класс службы в `lsp.py` (rust-analyzer) и строка в `SERVICE_FACTORIES`.
3. `toolchains/rust.py` — `class RustToolchain(Toolchain)`: `applies` (есть `Cargo.toml`), `run_targets`
   (бинарники из Cargo.toml), `run_command` (`cargo run`), `build_jobs` (`CommandSequence` с `cargo build`;
   свой разбор ошибок — подкласс `BuildJob`), `load_templates`/`create_project` (`cargo new`),
   `file_extensions = (".rs",)`, `file_names = ("Cargo.toml",)`.
4. `toolchains/__init__.py` — `register(RustToolchain())`.
5. Строки интерфейса — ключи в `locales/*.json` (тест `test_i18n` проверит и подпапки).

Отладка — тоже часть набора: `debug_available(ctx)` и `debug_config(ctx, target)` → `debug.session.DebugConfig`
(какой адаптер DAP запустить и какой запрос launch/attach ему послать). Всё остальное — общее для всех языков:
сеанс, точки останова, стек, переменные, значения при наведении. Python — `debugpy` (`python-debugpy`).
Проверка без настоящих отладчиков — `tests/fake_dap_adapter.py` (поддельный адаптер).

Список «Запуск», F5, «Собрать решение», «Создать проект» и обозреватель подхватят новый набор сами —
это проверяет тест `tests/test_toolchains.py::Extensibility` (игрушечный набор Echo).

## 9. Подсветка (`highlighter.py`)

Два подсвечивателя:

- `Highlighter` — свой, быстрый, для C#, Python, XML, JSON, Markdown. Умеет многострочные строки,
  атрибуты Unity (`[SerializeField]`) с учётом вложенности (`AttributeState`).
- `PygmentsHighlighter` — для всего остального (HLSL, GLSL, CSS, Rust, JS…). Перелексирует
  изменённый кусок с небольшой задержкой.

Цвета берутся из `theme.C`, поэтому при смене темы подсветка перестраивается (`rebuild`).

(`create_script`, `insert_text`, `message`, `generated`…), а `MainWindow` их ловит и действует.

## 11. Остальные модули

**Перенос типа в файл — `refactor.py`.** Читает текст, прячет строки и комментарии (`mask`), находит типы верхнего уровня (`parse`)
и строит план (`move_type_plan`): текст нового файла (using + namespace + тип) и кусок, который надо вырезать.
Окно (`move_type_to_file`) записывает файл, вырезает тип в одной правке (Ctrl+Z возвращает) и сохраняет исходный файл.
Вызов: меню «Правка», правый клик в C#-файле или `Ctrl+R, Ctrl+F`.

**Поиск по проекту — `search.py`.** Диалог `ProjectSearch` + поток `SearchWorker`.
Ищет по файлам на диске, но **для открытых вкладок берёт текст из памяти** (`buffers`), чтобы видеть несохранённые правки.
Поддерживает регулярки, целые слова, регистр, маски файлов, массовую замену.

**Шаблоны — `templates.py`.** Тексты новых файлов (`PYQT_WINDOW`, `UNITY_MONO`, `CS_CLASS`…),
список `TEMPLATES`, `render()` подставляет имя. `localize()` переводит комментарии внутри шаблонов.
`ensure_sample()` создаёт демонстрационный проект.

**Темы — `theme.py`.** Цвета хранятся **по ролям** в словаре `C` (фон редактора, панель, выделение…).
Источники: тема персонажа из `equestria-qt-kit` (необязательна) или собственные тёмная/светлая в духе Visual Studio.
Светлая/тёмная определяется по KDE или вручную. `ThemeController` рассылает сигнал `changed`.
Также здесь все значки — они **рисуются кодом**, картинок-файлов нет (`folder_icon`, `file_icon`, `tool_icon`, `app_icon`).
`theme.style(widget, "color:@dim@;")` — стили со вставкой цветов по именам ролей.
Цвета автоматически проверяются на читаемость (`_readable`, контраст 4.5).

**Перевод — `i18n.py`.** В коде — смысловые ключи `модуль.смысл` в `tr("mainwindow.save")`; тексты — в `locales/<код>.json`, образец для переводчиков — `en.json`. Описания Unity API — ключи `unity.<Класс>.<член>`.
Список языков **не записан в коде**: `i18n._discover()` смотрит файлы в `locales/` при запуске, и меню «Язык» строится из них.
Коды вроде `pt_BR` или `zh_TW` работают; если перевода нет — берётся базовый язык (`pt`, `zh`), затем английский.
Цепочка поиска: нужный язык → английский → сам ключ (чужой текст, например документация анализатора, возвращается как есть).
Язык определяется через `equestria-qt-kit` (`EQUESTRIA_LANG`), затем через переменные `LANGUAGE`/`LC_ALL`/`LANG`.
`bind_text(widget, "...")` привязывает текст к переводу, чтобы он обновлялся при смене языка без перезапуска.

**Обновления — `updates.py`.** Диалог для обновления Roslyn (через NuGet) и pyright (через npm).
Только по кнопке. После обновления новая версия **проверяется** (`lsp_self_test`: запуск + ответ на `initialize`).
Если проверка не прошла — автоматически возвращается прежняя версия.
`AnalyzerTool` → `RoslynTool`, `PyrightTool`; `UpdateWorker` работает в потоке.

**Параметры — `options.py`.** Каждый параметр — одна запись в `PAGES` (`BoolOption`, `NumberOption`,
`ChoiceOption`); окно «Средства → Параметры» (Ctrl+,) строит по ним дерево страниц, поля, поиск и «Сбросить страницу».
Значения читаются как `window.options["editor/font_size"]`, меняются только через `options.set(key, value)` —
так же поступают меню и горячие клавиши (Ctrl+Shift+., «Подсказки из неподключённых пространств имён»…).
После смены приходит `Options.changed(key)`, и `MainWindow._option_changed` применяет её.
Новый параметр: запись в `PAGES` + ветка в `_option_changed` + перевод в `locales/*.json`.

**Сохранность файлов — `documents.py`.**
- `atomic_write` — запись во временный `.имя.xxx.unipy-tmp` рядом и `os.replace`: при падении или нехватке места
  на диске остаётся прежний файл целиком. Через неё пишут редактор, переименование, перенос типа, быстрые действия.
- `DiskState` (у каждого редактора — `ed.disk`) помнит, что было на диске при открытии/сохранении.
  `DiskWatcher` следит за файлами вкладок (и перепроверяет все при возвращении в окно), `ExternalChanges`
  решает: нет правок — тихо загружает новую версию (`CodeEditor.reload_from`, одним Ctrl+Z), есть — спрашивает,
  когда окно активно. Удалённый файл помечает вкладку несохранённой. Перед сохранением `CodeEditor.save`
  ещё раз проверяет диск и спрашивает, если файл успели изменить.
- `RecoveryStore` раз в N секунд пишет копии изменённых вкладок в `~/.local/state/unipy-studio/recovery`.
  Копия удаляется при сохранении, закрытии вкладки и обычном выходе. После падения `MainWindow._offer_recovery`
  (при открытии проекта) показывает `RecoveryDialog`. Копии другого работающего окна (`owner` = pid + время запуска)
  не предлагаются.

**Лимиты логов — `log_limits.py`.** Не более 1 000 000 символов, 4000 блоков, 8192 символа в строке.
Защита от того, что вывод программы «съест» память.

## 12. Потоки и процессы — кто где работает

| Что | Где работает | Зачем |
|---|---|---|
| Интерфейс Qt | Главный поток | Только он может трогать виджеты |
| `JediWorker` | Поток `threading` | Python-подсказки |
| `CSharpIndexWorker` | Поток `threading` | Сканирование проекта и пакетов |
| `SearchWorker` | `QThread` | Поиск по файлам |
| `UpdateWorker` | Поток | Проверка и установка версий |
| Roslyn / csharp-ls | **Отдельный процесс** | C# анализ |
| pyright | **Отдельный процесс** | Python анализ |
| Запуск (F5), терминал | `QProcess` | Запускаемые программы |

Правило: из потока **нельзя** трогать виджеты. Поток кладёт результат в сигнал, главный поток его принимает.

## 13. Внешние зависимости

| Зависимость | Обязательна? | Что будет без неё |
|---|---|---|
| PyQt6 | **Да** | Не запустится |
| jedi | Нет | Подсказки Python только «по словам» |
| pygments | Нет | Языки без своей подсветки — простым текстом |
| equestria-qt-kit | Нет | Только свои темы UniPy; язык определяется своей логикой |
| Roslyn / csharp-ls (.NET) | Нет | C# подсказки только из встроенного справочника Unity |
| pyright (Node) | Нет | Python без проверок ошибок |

Идея везде одна: **всё необязательное при отсутствии не ломает запуск**, а тихо отключает свою часть.

## 15. Принципы, которых стоит держаться

1. **Окно — дирижёр.** Панели, редактор и службы общаются только сигналами через `MainWindow`.
2. **Ничего не ждём в интерфейсе.** Всё долгое — в поток или отдельный процесс.
3. **Устаревшие ответы выбрасываем** (проверка номера запроса `req`).
4. **Всё необязательное — необязательно.** Нет библиотеки → часть отключается, программа живёт.
5. **Одна запись вместо россыпи условий** (реестр языков, реестр служб).
6. **Всё ограничено по памяти** (логи, перезапуск серверов): программа должна быть лёгкой.
7. **Все тексты через `tr()`**, все цвета через роли темы `C`.

### Подсказки в коде (studio/insights) — как устроено

- **Слой поверх подсветки.** `highlighter.OverlayHighlighter`: сначала обычная подсветка строки (`_highlight`), потом
  `overlay(строка)` — список «начало, длина, изменить формат». Так семантика меняет цвет, не трогая курсив/жирный,
  а inlay hints добавляют символу перед подсказкой межбуквенный интервал — получается место, где `paint()` рисует плашку.
  Текст, курсор, стек отмены и «изменён» не меняются (проверено тестом).
- **Перекраска шлёт textChanged** (не `contentsChange`): `InsightController.rehighlight` глушит сигналы документа,
  а обновление подсказок ждёт `contentsChange` с настоящей правкой — иначе получилась бы петля и лишние проверки ошибок.
- **Ответы** приходят обычным путём (окно → `editor.on_worker_result`), `req` — ревизия документа: ответ на старый
  текст отбрасывается и запрашивается снова. Долгие задачи jedi уступают очереди (`JediWorker._interrupted`) и
  возвращают `partial` — контроллер повторит позже.
- **Слоты таймеров и сигналов — методы, не lambda**: lambda на контроллере, который сборщик мусора уже разбирает
  (цикл редактор ↔ контроллер), роняет процесс (SIGSEGV при срабатывании таймера).
- **CodeLens в конце строки**, а не над объявлением: `QPlainTextEdit` не умеет показывать строки, которых нет в тексте
  (`QTextBlockFormat.topMargin` его разметка игнорирует, и это правка со своим шагом отмены).
